# ДЗ1 · Шаг 1 — Анализ требований проекта

## Задача разработки

**Веб-приложение «Трекер привычек»** — SPA для ежедневного отслеживания привычек: список привычек, отметки выполнения по дням, серии (streaks) и простая статистика. Задача реальная и долгосрочная: это же приложение станет сквозным проектом курса (ДЗ3 — ТЗ и UI-концепции, ДЗ4 — Frontend, ДЗ5 — Backend + БД, ДЗ6 — CI/CD и интеграции).

Ориентировочный стек (фиксируется окончательно в ДЗ3–4): React + Vite + Tailwind CSS, Supabase (PostgreSQL) как бэкенд, деплой на Vercel.

## Ключевые требования к задаче (по Шагу 1 ДЗ1)

| Требование | Оценка для задачи | Что это значит для AI-инструмента |
|---|---|---|
| **Сложность** | Средняя: типовое SPA (10–20 компонентов), CRUD, авторизация, позже БД и пайплайн CI/CD | Не нужен «фабрика-прототипов» уровня no-code; нужен инструмент, уверенно работающий с типовым веб-стеком и умеющий дорабатывать код итеративно, а не только генерировать с нуля |
| **Доступ к локальным файлам** | **Нужен**: проект живёт в локальном git-репозитории; агент должен читать/править несколько файлов, видеть структуру проекта, работать с терминалом (npm, git, тесты) | Cloud-агенты (работают в браузере со своим окружением) проигрывают: код пришлось бы синхронизировать туда-обратно. Плюс для ДЗ4–6 нужны запуск тестов и деплой из репозитория |
| **Безопасность данных** | Умеренные: код учебный, но в ДЗ5 появятся авторизация, ключи Supabase и пользовательские данные; секреты не должны утекать в чужое облако; желательно, чтобы вендор не обучался на коде по умолчанию | Важна политика данных инструмента: обучение на пользовательском коде, приватные режимы, где исполняется/хранится код и ключи |
| **Бюджет** | Минимальный (студенческий): бесплатные тарифы или уже оплаченные инструменты; постоянная подписка $20/мес нежелательна | Бесплатные/включённые возможности решают; учитывается и доступность оплаты (международные карты, студенческие программы) |
| **Сроки и процесс** | Семестр, задания с дедлайнами; работа идёт evenings/weekends в VS Code | Инструмент должен встраиваться в существующее окружение (VS Code, git, GitHub), а не требовать отдельного рабочего процесса |

## Вывод (профиля требований для Шага 2)

Профиль задачи: **средняя сложность + обязательная работа с локальным репозиторием + умеренные требования к приватности + бюджет ≈ 0 + интеграция в VS Code/GitHub**. По этому профилю в Шаге 2 сравниваются 6 инструментов (минимум по заданию — 2 Cloud + 2 IDE/CLI):

- **Cloud-агенты:** Bolt.new, Lovable, Replit Agent
- **IDE/CLI-агенты:** Cursor, GitHub Copilot, Claude Code
