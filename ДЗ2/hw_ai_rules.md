# ДЗ2 · Шаг 1 — Проект и требования к системе правил

## Проект

**«Трекер привычек»** — сквозной проект курса (продолжение ДЗ1): веб-приложение для ежедневного отслеживания привычек — список привычек, отметки выполнения по дням, серии (streaks), статистика. В ДЗ3–4 проект получит ТЗ, UI-концепции и React-реализацию, в ДЗ5 — бэкенд на Supabase, в ДЗ6 — CI/CD.

**AI-агент:** Claude Code (выбран в ДЗ1: сравнительная таблица в `../ДЗ1/сравнительная_таблица.md`).

## Технологический стек

| Слой | Технологии |
|---|---|
| Frontend | React + Vite, Tailwind CSS, JavaScript с JSDoc (миграция на TypeScript по мере роста проекта) |
| Утилиты/логика | чистые функции ES-модулей, совместимые с Node и браузером |
| Backend / БД | Supabase (PostgreSQL, Auth, RLS) — с ДЗ5 |
| Тесты | node:test (утилиты), Vitest + Testing Library (компоненты — с ДЗ4) |
| Инфраструктура | Git/GitHub (feature-ветки → PR в main), деплой Vercel; Docker/CI — с ДЗ5–6 |

## Требования, которые должна обеспечить система правил (фиксация перед Шагом 2)

1. **Стиль кода** — единообразное именование и форматирование, чтобы код разных сессий агента выглядел как код одного автора; документирование экспортируемых функций (JSDoc) — код будут читать на проверке.
2. **Архитектура** — предсказуемая структура файлов (`src/utils`, `src/components`, `src/hooks`), чистые функции для логики (легко тестировать), разделение UI и логики.
3. **Качество и надёжность** — обработка ошибок и состояния loading/error/success в UI (прямо требуется критериями ДЗ4), тесты с краевыми случаями для новой логики (требование ДЗ4: ≥3 теста).
4. **Безопасность** — секреты только через переменные окружения (требование ДЗ5: `.env.example`, не `.env`); никаких «удобных» библиотек без спроса.
5. **Совместимость с курсом** — правила пишутся с прицелом на ДЗ4–6 (адаптивность, тесты, Supabase/RLS, CI), чтобы файл переиспользовался без переписывания.
6. **Язык** — комментарии и ответы агента на русском, идентификаторы на английском (соответствует языку курса).

Численные требования задания, которые закрывает файл правил: **строго не менее 10 правил суммарно**, разделы Роль / Контекст проекта / Стиль кода / Ограничения (≥2 строгих запрета) / Формат вывода, структура **Role-Context-Style-Constraints-Format**.
